Measured offline on 2026-10-30 with Node v22.23.4, on
`wv-208-journal-quadratic`, against starting revision `bc365b8`.
`node_modules` was already present; no install, network request, push or PR.
The starting revision already contains #339's locked journal and report-binding
indexes, so the issue's original quadratic execute baseline is no longer present.

## Contract and demonstrated red

`scaling.test.ts` asserts linear replay-key and snapshot-copy work for locked
zero-latency execution plus a completed resume after releasing and reacquiring
the writer lock. It checks exact dispatch counts, journal length and spend.
Wall-clock measurements are diagnostics; operation counts are deterministic gates.

Before implementation, three checks failed:

- Matching 400 intents against receipts sharing one binding inspected 80,201 call IDs
  (the bound is 1,200).
- Constructing a journal cloned an unused public snapshot once (the bound is zero).
- Threshold selection accessed report-only latency while selecting a grid point.

The implementation reuses indexed binding membership in execute, removes the
constructor's discarded clone, uses a receipt-ID set for pending report matching,
uses one report ledger snapshot, and computes only the three measures used to
select thresholds. Full reporting metrics, candidate order and tie-breaking stay
the same. The new checks and existing engine, journal, tuning and recorded-run
tests pass. The recorded-run tests provide existing independent evidence in
addition to the new synthetic complexity checks.

## Acceptance 3: suite duration and verification blockers

The first successfully launched `npm run test:decision-sites` baseline took
12.021 s; a repeat took 11.554 s. Both failed the four existing force-quit cases
because this managed runner loses child pipe output. Candidate took 9.769 s,
with only that same CLI test file failing (the other twelve files passed).
These are failing-command timings, not successful-suite throughput claims.
**A reduction of at least 15 s is impossible from this starting baseline.**

returns `EPERM`, dropping console output expected by the fixture assertions.

`spawnSync ... EPERM` and `listen EPERM ... 127.0.0.1`. No permissions or checks
were relaxed, and no workaround is part of the change.

Every top-level `checks/*.mjs` script was also run directly and exited zero,
including `source-scan.mjs`. The remaining verify commands were run individually:

- Passed: web typecheck/build, example and benchmark typechecks, Jev, entailment,
  decision, ChatGPT CLI, Muse Spark example, Nous example, Vercel example,
  frontier-weigh and weigh example tests.
- `task-acceptance:offline` completed the offline runner, then its existing CLI

- `test:decision-sites` passed engine, harness, sets, tuning, recorded reports,

The full-green acceptance boundary is therefore **unmet in this sandbox**.

## Acceptance 4 and remaining complexity

The append/fsync and single-writer-lock code is unchanged. `read()` and
`recordsFor()` still return independent mutable snapshots. Unlocked and read-only
handles still reload disk. Conservative pending reservations, full seven-field
identity including `request_digest`, render-only legacy binding and recovery
between receipt and budget-stop retain their existing passing targeted tests.

Intentional remaining costs outside the ordinary paired-row path:

- Repeated full public `read()` calls still copy every row for mutation safety;
  execute does not make one per entry.
- The journal's conservative fallback for unusual out-of-order receipts/intents
  can rescan the ledger/history. Repeated duplicate rows for the same call ID
  can also rescan that call's group. Those malformed/unusual histories are not
  the synthetic execution path, and their accounting semantics are preserved.
- Probability-only AUC still compares positive/negative pairs quadratically.
  This is existing descriptive scoring, separate from journal lookup.
- Report ordering still sorts records; matching histories is no longer quadratic.

Reproduce the new checks with:

```sh
export PATH=/home/box/.local/node22/bin:$PATH
node --experimental-strip-types benchmarks/decision-sites/scaling.test.ts
npm run test:decision-sites
npm run verify
for script in checks/*.mjs; do node "$script" || exit "$?"; done
```
